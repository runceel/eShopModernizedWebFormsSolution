# 移行先仕様: 画面・機能

見た目を除いて [現行画面仕様](../current-spec/02-screens.md) と [現行業務ルール](../current-spec/03-business-logic.md) を維持する。下記は合意済みの範囲と明示的な例外であり、未記載の挙動を変更してよいという意味ではない。

## 画面と URL

既存 URL にアクセスした際は、ブラウザ上の URL を変更せず対応する画面または画像を返す。商品 ID を含む URL は、その ID の商品を対象とする。

| URL | 機能 |
|---|---|
| `/`, `/Default`, `/Default.aspx` | 商品一覧 |
| `/Default/index/{index}/size/{size}` | ページ指定の一覧。`index` は 0 始まり |
| `/Catalog/Create`, `/Catalog/Create.aspx` | 商品登録 |
| `/Catalog/Details/{id}` | 商品詳細 |
| `/Catalog/Edit/{id}` | 商品編集 |
| `/Catalog/Delete/{id}` | 商品削除確認 |
| `/Catalog/Details.aspx`, `/Catalog/Edit.aspx`, `/Catalog/Delete.aspx` | ID のない直接アクセス。HTTP 500 を返し、内部例外やスタックトレースを表示しない |
| `/About.aspx`, `/Contact.aspx` | 現行の静的ページの内容を表示する。ナビゲーションに新たなリンクを追加することは求めない |
| `/Pics/{name}` | 商品画像 |

API 用 URL は別途設計する。存在しない商品 ID や不正なページ指定など、明示した URL 例外以外の扱いは[既知事項の移行方針](05-known-issues-policy.md)に従う。互換性の判断は [ADR 0004](../adr/0004-url-compatibility.md)。

### 外部リンクとの互換範囲

上表のルート、直接アクセス可能な `.aspx` パス、商品画像パスは、画面内にリンクがないものも互換対象とする。外部からのアクセス実績や利用頻度は未確認であり、利用がないとは推定しない。正常な旧 URL を新しい URL に置き換えたり、自動リダイレクトしたりしない。組み込み初期商品 ID 1〜12 と商品内容の対応を維持する。既存 SQL Server の実データ移行や公開環境のホスト名・配備先は第 1 ゴール対象外。

実装・ルート変更後は、[受け入れ基準の URL 確認方法](04-acceptance-criteria.md#url-互換性の確認方法)に従い、画面内リンク経由だけでなく旧 URL を直接確認する。ID のない3つの商品 `.aspx` パスだけを明示した HTTP 500 の互換例外とし、その他の異常入力へ一律に広げない。

## 未使用と見られる資産の移行範囲

| 現行資産 | 移行範囲 |
|---|---|
| About.aspx / Contact.aspx | 個別の画面として内容と上記 URL を維持する。Web Forms ファイル自体の移植は不要 |
| Site.Mobile.Master | Web Forms のマスターページは移植しない。各画面 URL と機能は維持する |
| ViewSwitcher.ascx | Web Forms の表示切替コントロールは移植しない。調査した現行構成には切替ルートの登録がない |
| CatalogItem.PictureUri | 未使用のプロパティは移植しない。商品画像の表示と `/Pics/{name}` は維持する |
| Edit の GetBrands / GetTypes | 未使用の画面メソッドは移植しない。編集画面のブランド・タイプ選択と現在値表示は維持する |

参照と公開経路の調査根拠は [OD-15](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/16)。旧環境の個別カスタマイズや実運用でのアクセス実績を確認したことは意味しない。

## 共通表示・遷移

- アプリ名は `Catalog manager` とし、Fluent UI の見た目を採用する。現行の色・レイアウト・フォントの再現は不要。
- 現行の表示項目、操作名、メッセージ、画面遷移は、明記した安全性・データ保護上の例外を除き維持する。
- 数値・日時の入力と表示は、現行の `en-US` カルチャを基準とする。
- ヘッダーから一覧へ戻れる。共通フッターには Blazor Web ホストのマシン名と UI セッション開始時刻を表示する。画面遷移では開始時刻を変えず、新しい UI セッションでは新しい開始時刻を表示する。この表示は第 1 ゴールのローカル利用でホストとセッションを識別しやすくするためで、公開環境で匿名利用者へホスト名を開示する判断ではない。
- 登録・編集・削除の成功後、および Cancel / Back to list から一覧へ戻る。詳細から対象商品の編集に進める。

## 画面上の名称

全画面の共通ヘッダーに `Catalog manager` を表示し、ブラウザーのタイトルにはページタイトルとアプリ名を含める。大文字小文字を維持し、アプリ名に `(Web Forms)` や `(Blazor)` 等のフレームワーク名を付けない。その他の利用者に見える箇所でアプリ名を表示する場合も同じ名称を使う。既存のブランドロゴや静的ページの本文を一律に改名しない。

| 画面（同じ画面の URL 別名・ページ指定を含む） | ページタイトル | ページ固有の見出し |
|---|---|---|
| 商品一覧 | `Home Page` | 現行はなし。共通の `Catalog manager` を表示し、新たな個別見出しは求めない |
| 商品詳細 | `Details` | `Details` |
| 商品登録 | `Create` | `Create` |
| 商品編集 | `Edit` | `Edit` |
| 商品削除確認 | `Delete` | `Delete` |
| About | `About` | `About.` |
| Contact | `Contact` | `Contact.` |

日本語の画面名は識別名であり、日本語の表示文字列への変更は行わない。現行の英語ページタイトル・見出しを維持し、操作名・項目名・確認文・検証メッセージも命名整理を理由には変更しない。タイトルの区切り文字等は固定しない。根拠は[現行画面仕様](../current-spec/02-screens.md)と OD-11 の記録であり、実装後に全 URL・共通ヘッダー・個別見出し・その他の可視箇所を確認する。

## 商品一覧

- 商品を ID 昇順に表示する。既定は 0 ページ目、1 ページ 10 件。
- 画像、Name、Description、Brand、Type、Price、Picture name、Stock、Restock、Max stock と、Edit / Details / Delete の操作を表示する。
- ページ数・件数と Previous / Next を表示する。商品が 0 件の場合は `No data was returned.` を表示する。
- 組み込み初期データでは 1 ページ目に ID 1〜10、2 ページ目に ID 11〜12 を表示する。CSV を選択した場合はそのデータを表示する。
- 一覧には Name、Description、Brand、Type、Picture name を対象とする大文字・小文字を区別しない検索と、Brand / Type の組み合わせフィルターを設ける。絞り込み後に ID 昇順、Name 昇順、Price 昇順 / 降順で並べ替え、同値は ID 昇順とする。検索・フィルター・並べ替えの変更時は 1 ページ目に戻る。結果は Catalog API の全ページを取得した後に Web 側で絞り込み、並べ替え、10 件ずつページ表示する。

## 商品詳細・登録・編集・削除

| 画面 | 操作と表示 |
|---|---|
| 詳細 | 対象商品の画像と Name、Description、Brand、Type、Price、Picture name、Stock、Restock、Max stock を表示する |
| 登録 | 上記の入力項目のうち画像はアップロード不可。新規商品の画像名は `dummy.png`、`OnReorder` は `false` |
| 編集 | 現在値を表示し、画像名は編集不可。画面にない `OnReorder` は更新時も既存値を保持する |
| 削除 | 確認文と商品内容を表示し、Delete で商品を物理削除する。Cancel では削除しない |

登録時の Price は `0.00`、Stock / Restock / Max stock は `0`、Brand / Type は先頭項目を初期選択する。編集時は既存の商品・ブランド・タイプの値を表示する。ブランド・タイプの管理画面や画像アップロード機能は追加しない。

## 入力・検証

現行の入力項目、正常値の範囲、既存の検証メッセージを基準とする。クライアント側だけでなくサーバー側でも検証し、不正な入力を保存しない。

| 項目 | 現行を基準とする内容 |
|---|---|
| Name | 必須。空欄時は `The Name field is required.` |
| Description | 任意 |
| Brand / Type | 既存の選択肢から指定する |
| Price | 0〜1,000,000。現行メッセージは `The Price must be a positive number with maximum two decimals between 0 and 1 million.` |
| Stock / Restock / Max stock | 整数の 0〜10,000,000。現行の各項目のメッセージを基準とする |

価格メッセージの「maximum two decimals」と、実際に現行 Validator / DB が受け付ける精度は同一とは限らない。価格表示は現行 DB モードを基準とするが、小数表示の実測は未了。入力の小数桁・空欄・保存時の丸め等は表示と区別して現行挙動を確認し、[既知事項の移行方針](05-known-issues-policy.md)の KI-12 と [OD-21](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/22) に従う。未実測値を確定仕様や検証合格としない。文字列を表示する際は HTML として実行されないようにする。

## 第 1 ゴールの適用範囲と確認

見た目以外の現行挙動は、明示的に合意した安全性・データ保護上の例外を除き維持する。レイアウト・色・フォントの視覚再現やピクセル一致は求めないが、表示項目・文字・意味・操作・遷移は外観の差を理由に省略しない。

| 範囲 | 対象と判断 |
|---|---|
| 画面・操作 | 一覧・ページング・詳細・登録・編集・削除、Cancel / Back to list、詳細からの編集、共通ヘッダー・フッター。削除は確認後に物理削除し、表示や Cancel だけでは削除しない |
| 入力・表示 | 画像、商品項目、選択肢・初期値、現行メッセージ、`en-US` の数値・日時、価格の `$` を維持する。画像アップロード、ブランド・タイプ管理画面は追加しない |
| 永続データ・画像 | 商品・ブランド・タイプの論理項目、関連、画像名と画像本体を維持する。組み込み初期データの ID 対応と現行形式 CSV・画像 ZIP を対象とする。ローカル PostgreSQL と画像を通常再起動で保持し、0 件でも再投入しない |
| URL・静的内容 | 一覧・商品 URL、直接アクセス可能な `.aspx`、About / Contact の本文、`/Pics/{name}` と画像内容を維持する。正常な旧 URL をリダイレクトしない |
| 資産そのもの | About / Contact は対象。未使用と調査した Web Forms 固有資産は移植しない。ただし既存画面、画像表示、編集のブランド・タイプ選択は維持する |
| 合意済みの例外 | サーバー側検証・出力エンコード・CSRF、編集時の `OnReorder` 保持と競合検知、画像保護、明示確認付きリセット、モック廃止と永続化を第 1 ゴールで扱う |

ローカルはログインなしで利用し、公開環境の認証・認可、クラウド配備、既存 SQL Server の実データ移行は対象外。旧 PostgreSQL スキーマからのデータ保持アップグレード試験は、実際に次のスキーマ変更を追加する時に行う。相関 ID は[ローカル運用方針](03-quality-and-operations.md#local-observability)に従い、旧形式の出力を要件にしない。未実測事項を残していることは、実装・検証完了を意味しない。

## 同時更新

複数の利用者が同じ商品を編集した場合、先に保存された後の古い版による更新を楽観的同時実行制御で拒否し、他の利用者の変更を上書きしない。

競合で保存を拒否された場合は編集画面に留まり、未保存入力（ドラフト）と選択値を保持する。利用者に保存失敗と競合を通知し、最新データの読み込みまたは編集を離れる操作を選べるようにする。通知文や配置は実装時に決めるが、保存成功と誤認させない。

| 競合後の操作 | 入力とデータの扱い |
|---|---|
| まだ選ばない／破棄確認をキャンセル | ドラフトを保持し、DB を変更しない。自動再読込・一覧遷移・入力消去をしない |
| 最新データを読み込む | 未保存入力を破棄することを明示して確認する。確認後、最新データ取得に成功した場合のみ表示と編集元の版を置き換える。取得失敗時は通知し、ドラフトを保持する |
| 編集を離れる／Cancel | 未保存入力を保存せず破棄することを明示して確認する。確認後に一覧へ戻り、DB は変更しない。他の画面内操作も確認なしでドラフトを捨てない |

再編集・保存は最新取得版に対して改めて競合検知する。ドラフトへの最新トークンだけの付け替え、自動再送、強制保存、自動マージは行わない。保証範囲は競合応答後の同じ編集画面内とし、ブラウザー終了や接続断を越える永続ドラフトは追加しない。[技術スペック](01-technical-spec.md#商品の同時更新制御od-13)と [ADR 0008](../adr/0008-product-concurrency.md)を参照する。
