# 移行先仕様: 品質・ローカル運用

## 対象と安全性

- 第 1 ゴールは同一 PC 内のローカル開発を対象とし、ログイン・認可を追加しない。Web、Aspire Dashboard、管理用入口は localhost からのみアクセス可能とし、API・DB は必要なサービス間通信に限定する。他端末・LAN やクラウドへ公開しない。これは公開環境への匿名アクセスを承認するものではない。
- localhost 制限は認証の代替ではなく、同一 PC 上の他プロセスや悪意ある外部サイトからブラウザーを経由する要求のリスクは残る。具体的なホスト・ネットワーク設定と、同一 PC からの利用および他端末からの到達不可は実装時に確認する。現時点で設定・検証済みではない。
- 認証の有無とは別に、匿名ローカル利用でも CSRF 等による不正な状態変更を防ぐ。Web のフォーム・対話とブラウザー到達可能な API の状態変更を対象に既定の保護を検証し、不足する入口を保護する。Origin 等の扱いを含む方式は実装時に定め、正規操作の成功、別オリジン等からの不正要求拒否、DB 不変を HTTP 統合・ブラウザーで確認する。対策・テストは未実施。
- 表示データの出力エンコード、サーバー側検証、編集時の `OnReorder` 保持、同時更新の検知により、セキュリティ・データ保護上の問題を修正する。
- エラーは利用者または操作者に失敗として通知し、内部例外・スタックトレース・秘密情報をブラウザに表示しない。接続情報や秘密情報をソースにコミットしない。
- 将来のデプロイ時は、認証・認可、TLS、公開範囲とサービス間のアクセス制御等を別途設計する。既知事項の個別方針は[既知事項の移行方針](05-known-issues-policy.md)を参照する。

## 起動・停止・初期化

- `aspire run` でローカルの Web、API、PostgreSQL および初期化処理を起動する。初期化の失敗を通知し、初期化前の DB に対する通常操作を受け付けない。
- 通常停止後の再起動で、カタログデータと利用する画像を保持する。商品をすべて削除していても、再起動時に商品を再投入しない。
- 組み込み初期データ、または設定された CSV・画像 ZIP を使用する。CSV・画像 ZIP を選んでいる場合は必要な入力を検証し、不足・不正なら初回起動時もエラーで停止する。現行の CSV 欠落時の組み込みデータへのフォールバックは行わない。
- 開発用 PostgreSQL には名前付きデータボリュームを使い、コンテナの通常停止・再作成を越えてカタログと初期化状態を保持する。DB はリポジトリ内や一時コンテナ領域に保存しない。画像も通常停止・再起動で保持するが、保存先は実装時に定める。
- 初期投入時に既存画像との衝突、所有関係が不明な画像、ZIP 内の領域外パスがある場合は既存画像を変更せず停止・通知する。CSV のタイプ・ブランド参照等を含む全入力を先に検証する。
- SQL Server 既存データの ETL は第 1 ゴール対象外。既存 PostgreSQL のスキーマ進化は Migrations で扱い、次の実スキーマ変更時にアップグレード前後のデータ保持をテストする。現段階では新規 DB の Migration、初期化、再起動、Migration 失敗時の停止を確認する。

### ローカル前提と確認（OD-20）

必須ツールは .NET 11 SDK、AppHost と互換な Aspire CLI、PostgreSQL 用 Linux コンテナと永続ボリュームを実行できる OCI ランタイム、Interactive Server と Dashboard を利用できるブラウザーとする。Docker Desktop を標準経路とし、Linux では Docker Engine も対象とする。Visual Studio、IIS、SQL Server LocalDB は必須条件ではない。

OS 方針は Windows・macOS・Linux のうち、採用する .NET SDK、Aspire CLI、ランタイム、PostgreSQL イメージ、ブラウザーの上流サポートが重なる版・アーキテクチャとする。Podman・Rancher Desktop は候補だが標準確認経路に加えない。具体的な版固定と OS ごとの起動実証は実装時に行い、上流資料だけでアプリの実証済みサポートとしない。.NET 11 互換性を確認できない組合せを黙って別ランタイムへ変更しない。

起動前に SDK・CLI、コンテナ稼働・イメージ取得・ボリューム、ポート、入力ファイル・画像領域のアクセス権、接続設定を確認する。欠落・不正・タイムアウトは失敗段階と対象を通知し、固定 sleep や無期限待ちで正常扱いしない。正常起動は Dashboard で DB の健康状態、今回の初期化成功、API/Web readiness を確認し、localhost の一覧・画像・対話可能な CRUD でも確認する。liveness や AppHost が稼働中であることを readiness の代わりにしない。

DB 接続、Migrations、入力・画像初期化、API 起動の失敗を隔離環境で注入する。CLI／Dashboard に失敗段階・ログを出し、API の通常操作を拒否する。Web が稼働している場合は利用不可を通知し、保存成功扱いや成功後の遷移をしない。Web 自体が起動できない場合は操作者の CLI／Dashboard に通知する。Web・Dashboard・管理用入口は localhost のみとし、プロキシ・公開ポートも含め他端末から到達できないこと、API/DB は必要なサービス通信のみであることを確認する。

<a id="local-observability"></a>

### 観測・秘密情報と相関（OD-20 / KI-14）

Web・API・初期化サービスは ServiceDefaults を基礎に OpenTelemetry のログ・トレース・基本メトリクスをローカル Aspire Dashboard へ送る。リソース状態・コマンド結果・readiness と失敗ログを合わせて調査する。旧 log4net 形式・ローテーションや Application Insights 送信を要件にせず、クラウド exporter・公開環境用 SLO・監視基盤は第 1 ゴールに追加しない。Dashboard は停止を越える履歴・監査ログ保存を保証しない。

ログは時刻、サービス／リソース、操作・段階、成否、安全な原因分類を含める。接続文字列・パスワード・トークン・Cookie・CSV 内容・要求本文を、ログ、trace、例外、CLI 結果、ブラウザーへ出さない。設定全体も出力しない。DB 資格情報は secret 指定の Aspire parameter とし、開発用 User Secrets または環境変数から供給する。API・初期化サービスだけに渡し、Web には渡さない。User Secrets・環境変数は暗号化保管庫ではないため、実値を文書・シェル履歴・commit に残さない。設定を解決できなければ成功扱いせず通知する。

旧相関 ID の不出力は推定であり、再現要件にしない。.NET の標準 Activity / W3C TraceContext の TraceId・SpanId でログと trace を相関し、独自 GUID や相関ヘッダーは導入しない。Web→API の HTTP と処理ログを同じ TraceId に関連付け、HTTP 外の初期化・リセットにも操作 trace と成否ログを設ける。別プロセス間の自動相関は仮定しない。相関 ID は認証・認可の根拠にしない。

実装後、代表 CRUD と失敗の Web/API span・ログを同じ trace で追えること、初期化・リセットの失敗ログを各操作 trace と確認できること、ダミー秘密値・入力を使った失敗時に CLI／Dashboard／ブラウザーへ実値や本文が現れないことを確認する。詳細と判断理由は [ADR 0010](../adr/0010-local-aspire-operations.md)。これらは実装・実証済みではない。

## DB リセット

リセットは利用者が明示的に Aspire のコマンドから実行する操作であり、通常起動時には実行しない。第 1 ゴールの対象はローカルのカタログ DB である。

1. 対象 DB と、商品・ブランド・タイプのデータを消去することを示し、操作者の明示的な確認を必須とする。確認が得られない場合やキャンセル時は変更しない。
2. **リセット実行時点で有効な設定**を使い、組み込みデータまたは CSV・画像 ZIP を選ぶ。設定を変更する場合は AppHost を停止し、変更した環境変数を設定したシェルで `aspire run` を再実行してからリセットする。即時反映は行わない。
3. CSV・画像 ZIP を選択している場合、必要なファイルや内容を消去前に検証する。不足・不正ならエラーを通知して中止し、DB と画像を変更しない。
4. 通常のカタログ操作はリセット完了まで停止し、利用者に一時利用不可と通知する。対象以外の DB を変更しない。
5. カタログデータを消去し、選択したデータを再投入する。選択した画像セットに含まれる画像のみ更新し、含まれない既存画像は残す。
6. 処理途中で失敗した場合は開始前の DB・画像への復旧を試みる。復旧できない場合や状態を確認できない場合は通常操作を停止したまま操作者に通知する。再起動後も復旧が確認できるまで通常操作を再開せず、失敗を成功として報告しない。

Dashboard と CLI の両方で、現在の AppHost・カタログ DB の非秘密識別情報、DB の消去範囲、画像の更新範囲、セット外画像を残すこと、有効な入力方式を示す。確認は既定値のない必須テキスト入力として宣言し、提示した対象・範囲に対応する値を実行側で照合する。CLI は named option、Dashboard は同じコマンドの入力欄で渡す。名前・値形式は実装時に定め、実 AppHost の help／入力画面で確認する。確認値は秘密でも権限でもない。

`ConfirmationMessage` は Dashboard の補助表示に限り、全 CLI 経路の安全保証に使わない。対話 CLI でも自動承諾せず、非対話・直接実行を含め確認欠落／空／不一致／キャンセル／対象不明は変更前に中止する。対象・範囲・設定が確認後に変わった場合は確認を取り直す。同一対象の初期化・リセットを排他し、入力検証後・変更前に通常操作を止める。DB と選択画像の開始前状態を復旧可能に保持し、失敗・中断時は復旧確認まで再起動後も操作を止める。DB とファイルの更新を単一トランザクションとは仮定しない。失敗／キャンセルは CLI 非ゼロ終了と安全な診断にし、Dashboard で成功表示しない。

このカタログリセットは開発用ボリューム全消去や画像領域の全削除とは異なる。ボリューム全消去は別保守操作とし、対象・範囲と操作者確認を要する。未確認の全消去コマンドを案内しない。テスト後始末は当該実行が作成した専用資源だけに限定する。

## 同時更新・エラー

- 同一商品の編集競合を検知し、後からの古い更新によって先の更新を失わない。競合で拒否した更新は部分保存もしない。利用者のドラフトを編集画面に保持し、明示的な破棄確認なしに最新データへ置き換えたり、画面内操作で離れたりしない。[機能仕様](02-functional-spec.md#同時更新)に従う。
- ID のない直接の商品 `.aspx` URL では HTTP 500 を返すが、内部情報は表示しない。その他の異常ケースの表示や応答は現行との互換性を基準に個別に決める。
- エラー通知と調査に必要なログ・相関 trace は上記のローカル観測方針に従う。停止を越える保存期間や公開環境の定量的な性能・可用性目標は第 1 ゴールで定めない。

## テストと対象外

[受け入れ基準](04-acceptance-criteria.md)は実装後の確認条件であり、今回の文書記録はテスト実装・実行を意味しない。[ADR 0006](../adr/0006-test-strategy.md)に従い、単体、WebApplicationFactory と Testcontainers for .NET の実 PostgreSQL を使う API 統合、Aspire.Hosting.Testing の AppHost 構成、少数の Playwright for .NET ブラウザーテストを併用する。xUnit を採用方針とし、各ツールの .NET 11 との互換性は実装時に確認する。

DB・画像を変更するテストは実行ごとに隔離した使い捨て DB、データボリューム、画像領域で行い、開発用の永続資源を使わない。再起動時の永続化もテスト専用資源内で確認する。破壊操作を開発データに対して実行しない。画面の視覚確認は一覧とフォームを代表として広い・中間・狭い幅で行い、主要操作が利用可能で、横にはみ出したり隠れたりしないことを確認する。旧画面の色・レイアウト・フォントやピクセル単位の一致は求めず、具体的な viewport は実装時に定める。公開環境の運用・バックアップ・復旧・認証は次段階の検討対象とする。
