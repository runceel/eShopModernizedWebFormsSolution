# 移行先仕様: 品質・ローカル運用

## 対象と安全性

- 第 1 ゴールはローカル環境を対象とし、ログイン・認可を追加しない。これは公開環境への匿名公開を承認するものではない。
- 表示データの出力エンコード、サーバー側検証、編集時の `OnReorder` 保持、同時更新の検知により、セキュリティ・データ保護上の問題を修正する。
- エラーは利用者または操作者に失敗として通知し、内部例外・スタックトレース・秘密情報をブラウザに表示しない。接続情報や秘密情報をソースにコミットしない。
- 公開時の認証・認可は次段階で検討する。既知の問題のうち、上記以外の修正範囲は [OD-10](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/11) で個別に決定する。

## 起動・停止・初期化

- `aspire run` でローカルの Web、API、PostgreSQL および初期化処理を起動する。初期化の失敗を通知し、初期化前の DB に対する通常操作を受け付けない。
- 通常停止後の再起動で、カタログデータと利用する画像を保持する。商品をすべて削除していても、再起動時に商品を再投入しない。
- 組み込み初期データ、または設定された CSV・画像 ZIP を使用する。CSV・画像 ZIP を選んでいる場合は必要な入力を検証し、不足・不正なら初回起動時もエラーで停止する。現行の CSV 欠落時の組み込みデータへのフォールバックは行わない。
- 対応 OS、コンテナランタイム、接続設定、ヘルスチェックやログ・トレースの具体的な構成は [OD-20](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/21) で決める。

## DB リセット

リセットは利用者が明示的に Aspire のコマンドから実行する操作であり、通常起動時には実行しない。第 1 ゴールの対象はローカルのカタログ DB である。

1. 対象 DB と、商品・ブランド・タイプのデータを消去することを示し、操作者の明示的な確認を必須とする。確認が得られない場合やキャンセル時は変更しない。
2. **リセット実行時点で有効な設定**を使い、組み込みデータまたは CSV・画像 ZIP を選ぶ。設定変更を実行中のアプリに反映する具体的な手順は未決定。
3. CSV・画像 ZIP を選択している場合、必要なファイルや内容を消去前に検証する。不足・不正ならエラーを通知して中止し、DB と画像を変更しない。
4. 通常のカタログ操作はリセット完了まで停止し、利用者に一時利用不可と通知する。対象以外の DB を変更しない。
5. カタログデータを消去し、選択したデータを再投入する。選択した画像セットに含まれる画像のみ更新し、含まれない既存画像は残す。
6. 処理途中で失敗した場合は開始前の DB・画像への復旧を試みる。復旧できない場合や状態を確認できない場合は通常操作を停止したまま操作者に通知する。再起動後も復旧が確認できるまで通常操作を再開せず、失敗を成功として報告しない。

CLI の確認方法、非対話実行での明示的な確認の渡し方、Dashboard の提供範囲、同時実行の制御、途中失敗・プロセス中断からの具体的な復旧方式は [OD-04](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/5) / [OD-20](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/21) で決める。確認がない非対話実行もリセットしてはならない。現時点で DB とファイルの更新が単一トランザクションであるとは決めていない。

## 同時更新・エラー

- 同一商品の編集競合を検知し、後からの古い更新によって先の更新を失わない。競合を利用者に通知する。
- ID のない直接の商品 `.aspx` URL では HTTP 500 を返すが、内部情報は表示しない。その他の異常ケースの表示や応答は現行との互換性を基準に個別に決める。
- エラー通知と調査に必要なログは残す。ログ項目・トレース・保持期間や、定量的な性能・可用性目標は未決定。

## テストと対象外

[受け入れ基準](04-acceptance-criteria.md) は仕様の確認項目であり、すべての自動化や特定ツールの採用を決めるものではない。テスト対象と実行方法は [OD-17](https://github.com/runceel/eShopModernizedWebFormsSolution/issues/18) で決める。公開環境の運用・バックアップ・復旧・認証は次段階の検討対象とする。
