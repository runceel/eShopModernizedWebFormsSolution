# 移行先仕様: 受け入れ基準

合意済みの仕様を確認するための条件であり、実装や検証が完了したことを示さない。AC-01〜24 の既存番号は維持する。未公開の Issue ブランチ間で AC-25 以降の番号が重複しているため、本統合では後続の条件を名前付きシナリオとして記し、番号体系が確定したとは主張しない。未決定事項は合否条件を仮決めせず、実装時に確定する。DB リセットや失敗注入は、対象を確認した隔離テスト環境でのみ実施する。

## 起動・データ

| ID | 操作・条件 | 期待結果 |
|---|---|---|
| AC-01 | 組み込みデータ設定の未初期化 PostgreSQL で `aspire run` | EF Core Migrations が合意済みのスキーマを作成し、初期化後に API と Web が利用可能になる。Migration 失敗時は利用可能にならず、失敗が通知される |
| AC-02 | AC-01 のスキーマとデータを確認 | `catalog` / `catalog_brand` / `catalog_type` の型・長さ・NULL・PK・FK が[技術スペック](01-technical-spec.md#カタログデータ)と一致する。ブランド 5 件、タイプ 4 件、商品 12 件、組み込み商品 ID 1〜12 と各 ID の内容は[現行初期データ](../current-spec/04-data.md#44-初期データ)と一致し、全 FK が解決する |
| AC-03 | 初期投入後に商品を作成 | 既存商品と重複しない ID が採番され、画像名は `dummy.png`。欠番や連番は合否条件にしない |
| AC-04 | 商品の作成・編集後に通常停止し、再度 `aspire run` | 変更したデータ・利用画像を保持し、Migration の再適用でデータを失わず、初期データは重複しない |
| AC-05 | 全商品を削除して停止・再起動 | 商品は 0 件のまま。再起動を理由に再投入されない |
| AC-06 | CSV・画像 ZIP を選択し、未初期化 DB で起動 | 選択入力の全行を初期化し、全ブランド・タイプ参照が解決する。CSV 価格は invariant culture で解析し、画像本体はファイルに保持する |
| AC-07 | CSV・画像 ZIP を選択し、必要な入力を不足または不正にして初回起動 | エラーを通知し、通常操作を受け付けない。DB に部分投入せず画像も変更せず、組み込みデータへ自動で切り替えない |

### URL 互換性の確認方法

AC-08〜12 は[画面と URL の一覧](02-functional-spec.md#画面と-url)の全パターンを対象とする。実装後、準備完了した Web・API・専用 PostgreSQL・画像領域で、限定的な Playwright for .NET 回帰と HTTP 確認を行う。これは実装後の条件であり、検証済みの結果ではない。

- 旧 URL をブラウザーへ直接入力し、HTTP 応答、最終 URL、内容を確認する。HTTP 確認では自動リダイレクト追従を無効にし、正常 URL が 200、3xx や自動遷移なしであることを確認する。
- `/`、`/Default`、`/Default.aspx`、ページ指定の 0・1 ページを直接開き、URL を維持したまま組み込みデータ ID 1〜10／11〜12 を確認する。Previous / Next では移動先 URL と商品範囲を確認する。
- 登録の両 URL、詳細・編集・削除 URL で組み込み商品 ID 1〜12 と内容の対応を確認する。CRUD、Cancel / Back to list、詳細から編集は対話有効後に確認する。
- About / Contact は本文・住所・連絡先リンクを確認する。`/Pics/1.png`〜`/Pics/12.png` と `/Pics/dummy.png` は直接 HTTP 取得と画像内容を確認する。
- ID なしの Details / Edit / Delete `.aspx` はそれぞれ URL を維持して HTTP 500、内部例外・スタックトレース非露出を確認する。画面がエラー風でも HTTP 200 なら不合格。これを他の異常入力へ一般化しない。

### 商品同時更新の入力保護シナリオ

AC-16 は API／実 DB 統合で原子性を、次の操作は独立した二つのブラウザーセッションで確認する。Interactive Server の操作が有効になってから行う。テストは実行ごとに隔離する。

| シナリオ | 期待結果 |
|---|---|
| 競合応答後に何も選ばず待つ | 保存失敗と競合を通知し、編集画面・全入力・選択値を保持する。自動遷移・再読込・入力消去・強制保存はない |
| 最新データ読み込みの破棄確認をキャンセル後、確認して読み込む | キャンセル時はドラフトを保持する。確認後の取得成功時だけ最新データと版に置き換わる。再編集はその版で競合検知される |
| 編集を離れる／Cancel／一覧への操作で破棄確認をキャンセル後、確認して離れる | キャンセル時はドラフトと画面を保持し、確認後だけ未保存入力を破棄して一覧へ戻る。DB は変更しない |
| 破棄確認後の最新データ取得に失敗 | 失敗を通知してドラフトを保持する。空の入力への置換や一覧遷移をしない |
| 同じ版による API 更新を同時送信し、古い版の再送や欠落・不正トークンも試す | 成功は一つのみ。他は競合・拒否となり成功値を保持する。無条件更新へフォールバックしない |

### 追加シナリオ（未採番）

次の名前付きシナリオは、複数の Issue ブランチで後続 AC 番号が衝突していたため、本統合で整数番号を割り当てていない。既存 AC の番号体系を正規化する主張ではない。

| シナリオ | 操作・条件と期待結果 |
|---|---|
| PostgreSQL スキーマと物理名 | Migration 後にテーブル・列・型・NULL・PK・FK が[技術スペック](01-technical-spec.md#カタログデータ)と一致する。小文字 `snake_case` と制約名規約を確認し、`numeric(18,2)`、商品 Name 最大 50 文字、必須関係、参照先削除の `RESTRICT` を確認する。未合意の CHECK・二次インデックスを追加しない |
| IDENTITY と再起動・リセット | 初期化／CSV／リセットで明示 ID を投入した後や通常再起動後も、新規商品・ブランド・タイプの ID は既存値と衝突しない。欠番は許容し、連番を要求しない |
| 初期化状態と部分失敗 | 成功記録のない DB に既存カタログや判別不能な管理領域があれば変更・投入せず停止する。初回シードと成功記録は同一 DB トランザクションで確定し、シード・画像配置・採番調整中の失敗／中断後は重複投入や既存画像の上書きをせず、状態の確認・復旧まで停止する |
| 成功済み DB の Migration 失敗 | 成功済み DB でも今回の Migration 失敗または確認不能時は、過去の成功記録だけで通常操作を許可せず、失敗を通知する。自動リセット・再投入をしない |
| CSV・画像 ZIP の入力形式と安全性 | 現行形式の `CatalogTypes.csv`、`CatalogBrands.csv`、`CatalogItems.csv`、`CatalogItems.zip` と商品 CSV 任意列欠落を受け付ける。相対パスは AppHost プロジェクト基準、絶対パスも利用可能で、作業ディレクトリに依存しない。全ファイル・ヘッダー・行・参照先を先に検証し、一つでも不正なら DB・画像を変更しない |
| 初期画像衝突・ZIP 境界 | 初回投入先に衝突画像や所有関係不明の画像があれば変更せず停止する。ZIP の領域外パスを拒否し、画像領域外を変更しない。リセットでは選択セット外の既存画像を残す |
| 画面名・レイアウト・未使用資産 | 各 URL のブラウザータイトル、共通ヘッダー、個別見出しに[機能仕様](02-functional-spec.md#画面上の名称)の名称を使う。視覚確認は一覧とフォームを広い・中間・狭い幅で行い、主要操作が隠れず横にはみ出さない。未使用資産そのものは移植しないが、合意済みの画面機能は維持する |
| CSRF | ログインなしの正規登録・編集・削除が成功し、外部オリジン等からの不正な状態変更や、適用される検証情報の欠落・不正を拒否して DB を変えない。Web 対話とブラウザー到達可能な API を HTTP 統合・ブラウザーで確認する。具体的な保護方式は実装時に決める |
| ローカル起動・依存 readiness | 採用 OS／ツール組合せを記録する。DB 健康状態→今回の初期化成功→API ready→Web ready を実 `aspire run` で確認し、Running/liveness や固定 sleep だけを合格にしない。localhost 一覧・画像・Interactive Server CRUD が利用可能 |
| 起動・実行中の失敗停止 | DB 接続・Migration・初期化・画像・API 失敗を隔離環境で注入する。CLI／Dashboard に失敗段階とログがあり、API 操作を拒否する。Web 稼働中は利用不可を通知し、保存成功扱いや成功後遷移をしない。中断・状態不明は再起動後も復旧確認まで停止 |
| localhost とサービス境界 | Web、Dashboard、管理入口は同一 PC からのみ利用可能で、プロキシ・公開ポートも含め他端末から到達不可。API／DB は必要なサービス間通信だけを許可する |
| リセットの両経路 fail-closed | Dashboard と対話／非対話 CLI で対象・消去範囲・画像更新範囲を提示する。同じ必須確認入力が明示された場合のみ実行し、欠落・空・不一致・キャンセル・対象曖昧・確認後の対象／設定変更では変更しない。CLI は失敗・キャンセルを非ゼロ終了で返す |
| リセットの排他・復旧 | 重複リセットと初期化の競合で並行変更しない。DB／画像変更失敗・プロセス中断時は復旧を試み、確認まで操作を停止する。対象外 DB と選択セット外画像は保持し、カタログリセットをボリューム全消去と混同しない |
| 相関トレース | 代表 CRUD と失敗の Web/API span・ログを同じ TraceId で追跡する。HTTP 外の初期化／リセット失敗も各操作 trace と相関する。独自 ID、旧ログ文字列形式、ブラウザーへの ID 表示は要求しない |
| 秘密・入力データの非露出 | ダミー資格情報・トークン・CSV 入力で失敗を発生させ、CLI／Dashboard のログ・trace・結果とブラウザーに実値・本文が現れない。Web に DB 資格情報を渡さず、設定欠落を成功扱いしない |

これらは実装後の合否条件であり、今回の文書統合でアプリ起動、ランタイム、実 DB、ブラウザー、テストのいずれかを実証したものではない。
